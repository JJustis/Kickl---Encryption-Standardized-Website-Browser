What it does

Eight ideas, one sealed spine.

Every surface in the app is built on the same primitives: a name, a sealed package, and a key that never leaves memory. That is why the parts fit together.

Sealed documents

Pages are KML packages, not HTML bundles. Structure is public; notes, files and keys are blobs under AES-256-GCM.

no scripts · no trackers

Names, not addresses

A lookup is a fresh P-256 ECDH session; the query and the reply travel inside AES-256-GCM, then the session keys are wiped.

PFS phonebook

KicklMail

Letters travel to a short id, sealed end to end, and cross the wire over TLS 1.3 pinned to the recipient’s own signed key. The vault unlocks with a separate mail key and re-locks on a timer.

sealed letters

FreeChat

A group secret wrapped in ML-KEM-1024, per-epoch keys, messages sent as PNGs. The relay carries ciphertext it cannot read, every message is signed, and your browser pins each member’s keys and warns when one changes.

post-quantum room

Native ads, no beacons

Nickles placements are minted for one site and one slot, resolved locally, and rotate in ten-minute buckets. No impression ping.

own the placement

Arcade & ownership

Tic-tac-toe and Memory play natively, offline. Bigger games run as sandboxed WebAssembly, and a name you buy is yours by certificate, not by password reset.

playable today

paid in Bitcoin · sealed by the CA

Under the hood

Cryptography you can read in an afternoon.

One symmetric cipher does every job, so there is one nonce discipline, one tag check, and one implementation to audit. Asymmetric keys only wrap or agree — they never hold your content.

  1. 01

    One AEAD, everywhere

    AES-256-GCM seals blobs, cache entries, keystrokes, transport frames and title tokens.

  2. 02

    Wrapping, not encrypting

    RSA-3072-OAEP wraps a fresh AES key for an origin device; P-256 ECDH + HKDF splits lookup keys.

  3. 03

    The phonebook is signed twice

    Registry snapshots carry Ed25519 and ML-DSA-65 signatures over the same message. No classical-only fallback.

  4. 04

    Fail closed, then report

    A package that misses the registry hash is never parsed. The mismatch bumps an attack counter instead.

The central server

Sealed pages

A page you can trust without trusting the site.

The renderer speaks one small markup language and nothing else. That is the whole security model of the surface — there is no capability to disable, because there is no capability to call. A page's text and public files are encrypted on disk but open for any reader by design; parts the author marks protected stay locked until the reader has the key.

✓ A KICKL page can

  • Headings, paragraphs, quotes, code and rules
  • Sealed images and files as encrypted blobs
  • Inline SVG art drawn from the document itself
  • Native ad slots minted for that one placement
  • Names resolved and hashes verified before parsing
  • Sandboxed WebAssembly games, only after you press play
  • A verified-owner badge, if its owner had the CA seal it

✕ A KICKL page cannot

  • Run JavaScript — the element does not exist
  • Reach the network or your files from a game
  • Read your clipboard, files or device
  • Load a third-party script or font
  • Phone home an impression or a pixel
  • Change after the registry hash was signed

Claim a site

Every name is free until someone owns it.

Anyone can create and edit a jttp:// page on a name nobody owns, for free. When you want a name to be yours alone, you buy it with Bitcoin. The shop gives you an ownership certificate — a small file — and from then on only a holder of that file can publish to the name.

  1. 01

    Press CLAIM SITE

    On any page, the button opens the BTC shop with the name already filled in. Nothing is bought until you pay.

  2. 02

    Pay at the BTC shop

    Send the exact amount shown. When the payment confirms, download your certificate, a .kcert file.

  3. 03

    Import it, and it is sealed

    Choose the file in the browser. It is checked, kept encrypted in your profile, and sent to the CA to be sealed. Better still, set an owner passphrase on the shop page when you order: the shop signs a hash of it into your certificate, so the file alone can no longer edit your name.

  4. 04

    Edit with the certificate

    Open jttp://yourname/edit. The page asks for the file and your passphrase; without both nobody else can change your site, and the copies you save are passphrase-locked too.

The certificate is a key: whoever holds the file owns the name until the claim expires, so keep it safe. A name lasts twelve months; claiming it again retires the old certificate.

The Kickl CA

Someone is watching the certificates.

A certificate authority checks that each ownership certificate is genuine, that no one holds a clashing claim, and writes everything it signs into a public, append-only log. A site whose certificate the CA has sealed shows ✓ VERIFIED OWNER to every visitor, not just to its owner. Nothing is done by hand: every certificate gets the same checks, automatically.

✓ The CA checks

  • The shop's signature on the certificate is genuine
  • The certificate has not expired or been revoked
  • No newer or clashing claim exists for that name
  • Every seal is written to a public transparency log

✕ The CA refuses

  • Certificates from a shop it does not trust
  • A second, different claim on the same name and number, and it logs the attempt
  • Old certificates after a name is claimed again
  • Anything its root has revoked
  1. 01

    An offline root

    Signs only the issuing key. Its public half is built into the browser, so a browser trusts nothing it was merely shown.

  2. 02

    A short-lived issuing key

    Signs the seals and is renewed every 90 days. A leaked key stops being useful on its own; the root can also revoke it.

  3. 03

    Hybrid signatures, a public log

    Every signature needs both Ed25519 and ML-DSA-65 to verify. Each seal carries a proof that it is in the log, which anyone can audit.

A seal shows the CA saw and logged a genuine certificate. It does not say who the buyer is. The CA ships with a maintenance script that checks it daily and renews its issuing key before it expires; a failed audit or a changed shop key is flagged to a person, never quietly fixed.

WebAssembly

Games, run in a cage.

KICKL pages still have no JavaScript. Games and interactive pieces use WebAssembly instead: a compact, compiled format you can build from Rust, C, Zig, AssemblyScript or Go. A game is sealed into the page like any other file, and it runs in a sandbox that gives it nothing to reach with.

  1. 01

    It imports nothing

    No network, files, clipboard, clock or host calls. A module that asks the browser for any of them is refused before it starts.

  2. 02

    Fuel and a memory cap

    Every frame runs on a fixed instruction budget, so an endless loop stops the game, not your browser. Memory growth is capped too.

  3. 03

    You press play

    Nothing runs on load. It stops when you leave the page, switch tab, lock the profile or close the window.

  4. 04

    Saves stay yours

    A game can keep up to 4 KB, such as a best score. It is stored encrypted in your own profile, never on the page.

Checked in the open

What we found, and what we have not fixed.

The code has had a written security audit in three rounds, by its author, with every finding, fix and open item published. It is not a substitute for an independent review, and it says so.

  1. 01

    Mail is TLS 1.3, pinned

    Direct mail travels over TLS 1.3 to a key the recipient signed into their own address. No plain-http fallback, capped connections, hard timeouts.

  2. 02

    Hostile input is fuzzed

    Pages, feeds, registry answers, certificates, mail bundles, pictures and WebAssembly modules are mutated thousands of times in the tests. Image and SVG bombs are capped.

  3. 03

    One CA, keys under lock

    The browser trusts only secupgrade.com/secca. The CA and shop signing keys are wrapped with the operating system and never sit in the repository.

  4. 04

    The gaps are listed

    FreeChat's server still decides who is in a room, a certificate bought without a passphrase is a bearer file, and secrets held in managed memory cannot be wiped.
